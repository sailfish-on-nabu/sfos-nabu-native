# nabu 原生相机

当前 GStreamer 插件版本为 0.11，配合 Qt 相机设备桥接库，让 Jolla 相机使用主线 CAMSS 的 OV8856 前摄和 OV13B10 后摄。设备上的前后摄切换已由用户确认，拍照按钮也已由用户确认恢复；两个镜头都通过 Qt 后端实际拍摄和 JPEG 保存测试。

内核需要启用 CONFIG_VIDEO_OV13B10、CONFIG_VIDEO_OV8856 和 CONFIG_VIDEO_CN3927。nabu-camera-setup.service 在开机时加载模块并配置 CSIPHY0 → CSID0 → VFE0 RDI0 后摄通路及 CSIPHY1 → CSID1 → VFE1 RDI0 前摄通路。初始化程序按 CAMSS 驱动识别媒体图，捕获插件按 VFE 节点名称找设备，避免依赖启动时的节点编号。

相机源读取 packed RAW10，每个 2×2 Bayer 单元输出一个 RGB 像素。前摄为 820×616，后摄为 1052×780。图像处理包括估计黑电平、sRGB 亮度曲线、模拟增益反馈、较亮中性区域的白平衡，以及对较淡颜色的色度增强。配置位于 /etc/nabu-camera.conf，默认前摄，色度增强峰值 3.3。前摄初始红、蓝增益分别为 1.40、1.67；后摄根据实测中性区域设置为 1.40、1.64，修正原先使用 1.0 时的绿色偏色。

后摄已从只读中央区域的 1364×768 模式改为保留完整传感器视野的 2104×1560 合并模式，VBLANK 将默认 60 fps 改为 30 fps；RGB 输出为 1052×780。4208×3120 全尺寸模式虽然通过原始捕获及 JPEG 测试，但用户报告明显延迟，所以采用合并模式。源处理落后时丢弃积压的旧帧，优先输出最新帧。

后摄源打开 CN3927 对焦器，通过中心区域的原始绿色通道梯度进行粗搜和细搜，选择清晰度最高的位置。首次搜索期间暂缓向 Qt 发布拍照就绪状态；关闭时恢复进入前的对焦位置并释放对焦器。连续画面的清晰度明显下降时再次搜索。设备实测选择位置 416 后完成曝光事件和 JPEG 保存。界面点按焦点选择仍没有接入。

qtcamera.cpp 提供 Qt 5.6 QGstUtils 相机枚举函数的兼容实现，返回 nabu-front 和 nabu-rear，声明对应镜头位置和安装角度。Qt 默认枚举不识别 CAMSS 的多平面节点，空设备列表会让它跳过原生源选择和界面的镜头切换。

首帧到达后（后摄则等待首次对焦完成），相机源通知 wrappercamerabinsrc 发布实际的 ready-for-capture 状态。Qt 5.6 原先只监听状态变化，没有读取包装源启动时已为真的状态，因而预览正常时拍照按钮仍不可用。静态拍摄请求到达后，原生源在下一张真实帧取得时发送 photo-capture-start，供 Sailfish Qt 后端触发 imageExposed。Jolla 相机使用这一事件播放快门声和拍后动画；该事件和 JPEG 保存都已通过设备上的 Qt 测试。拍后动画已由用户确认恢复。当前普通模式的 system.sound.level 原为 0，已恢复到系统默认值 1。prepare-nabu-camera-sound.py 生成 160 毫秒的短双音，避免机械快门录音的宽带噪声，以独立声音主题名称 nabu-camera-shutter 安装。安装后删除旧的 PulseAudio 声音样本，确认新缓存长度为 0.160 秒。曾试验降低模拟增益并补偿数字增益；用户随后报告声音设置播放变成噪音，该试验已撤回。设备和构建配置恢复为四组数字音量 529、模拟音量 6，PulseAudio 音量保持 39134。设置声音恢复情况和新快门提示音听感仍待真机确认。

普通相机图标和锁屏入口使用 silica-qt5 启动器及单实例模式，旧的相机媒体预加载实例已屏蔽。Sailjail 保持启用，NabuCamera.permission 提供配置文件、原生图形库路径、Qt 相机桥接库和原生 GStreamer 源选择。

系统旋转使用 source/nabu-sensors/ 的真实 SSC 加速度桥接。Qt 的 Sensors.conf 声明加速度和方向后端，SensorFW 使用 evdev 加速度适配器及方向计算链。Qt 客户端已能读取方向；用户已确认相机按钮能随设备转动。原生 RGB 预览另外通过 ViewfinderOutput 仅校正安装角度：该预览位于固定窗口，不再重复补偿页面旋转。前后摄安装角度均为 270°；前摄额外使用两倍页面角度补偿其朝向关系，后摄只校正安装角度，并使用 PreserveAspectCrop 填充。用户已确认画面与旋转正常。

反复打开相机时的 CCI 首次传输超时修正位于内核 i2c-qcom-cci.c 和 ov8856.c：nabu 上超时传输在控制器重置后重试一次，前摄每次启动重新检查通信。两个模块已安装并加载到设备；保持正常自动运行时休眠时，连续三次关闭、等待两秒、重新捕获 30 帧均通过。

scripts/build-nabu-camera.sh 使用固定校验值的 ARM64 开发头文件、交叉 C++ 前端和 Sailfish 运行库构建两个插件；原生 RPM 已接入插件、初始化模块、配置和服务。运行库仍来自目标 Sailfish 系统。

这些修改已部署到 192.168.3.241，备份位于 /var/tmp/nabu-camera-install.0_vv2lrl。调试和安装证据位于 work/logs/camera-20261121/、camera-install-20261121/ 和 camera-sensors-20261121/。当前发布镜像尚未重建，也未进行整机重启验证；没有使用 QEMU。

当前仍是基础软件 ISP，拍照分辨率等于预览分辨率，缺少完整的曝光时间、传感器色彩和镜头阴影校准。录像未完成验证。
